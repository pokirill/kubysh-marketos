## Статья 1 · чт 01.10, 10:00

**Заголовок:** ИИ объясняет, приложение считает: почему я убрал языковую модель из кнопки, которая раскладывает деньги

**Теги:** ИИ, LLM, iOS, Swift, продуктовая разработка

В моем приложении для личных финансов была кнопка «Показать Кубышу». Она раскладывала накопления по целям:
сколько положить в подушку, сколько в отпуск, сколько в машину. Работала через языковую модель. У части людей
вместо ответа она показывала «работает только с VPN».

Я переписал ее на обычный алгоритм. Он умещается в один файл, работает без сети и отвечает мгновенно. Ниже
почему модель там была лишней, как устроен алгоритм и где модель в приложении осталась.

### Что за кнопка

[ПЕРЕСКАЖИ: коротко про Кубыш. План от получки до получки, все накопления на одном счете, а в приложении они
разложены по целям, как по конвертам. У каждой цели сумма, приоритет и желаемая дата.]

Когда целей несколько, возникает вопрос: как разложить уже накопленное, чтобы все успели к своим датам. Для этого и
была кнопка. Модель получала список целей, суммы и даты и предлагала раскладку.

### Что пошло не так

**1. Доступность.** Модель работает на внешнем сервисе. На мобильном интернете в России внешние сервисы доступны не
всегда, и человек без VPN получал отказ. [ПЕРЕСКАЖИ: как ты это заметил.]

**2. Один вопрос, разные ответы.** Нажал кнопку дважды, получил две разные раскладки. В тексте это нормально, в
деньгах подрывает доверие: какой из двух ответов правильный?

**3. Ответ нельзя проверить тестом.** Нельзя написать тест «модель разложила правильно». Можно только смотреть
глазами.

**4. Даты не совпадали с остальным приложением.** Дату каждой цели в Кубыше считает календарный движок: по доходу,
премиям и плану пополнений. Модель называла свои даты, и они расходились с карточками целей на соседнем экране.

### Это не задача для модели

Если убрать слова, задача оказывается оптимизацией с двумя режимами:

- **«Быстрее»:** отдать деньги целям по очереди, чтобы первые в очереди собрались как можно раньше;
- **«Успеть к датам»:** положить в каждую цель минимум, при котором она успевает к желаемой дате. Остальное
  остается свободным, его можно потратить на себя.

**Очередь** та же, что в календарном движке: сначала приоритет (критичная, важная, хотелка), потом ближайшая
желаемая дата. Если очередь будет своя, раскладка и даты снова разойдутся.

**Минимальная сумма.** Чем больше денег уже лежит в цели, тем раньше она собирается. Дата монотонно зависит от суммы,
значит, минимум можно найти бинарным поиском. Точность до рубля не нужна, шаг 1 000 ₽:

```swift
/// Наименьшая сумма (шаг 1 000 ₽), при которой цель успевает к желаемой дате.
static func minimalAmount(upTo cap: Double, index: Int, goals: [Goal], target: Date,
                          forecast: ([Goal]) -> [UUID: Date]) -> Double {
    func onTime(_ amount: Double) -> Bool {
        var probe = goals
        probe[index].currentAmount = amount
        guard let date = forecast(probe)[probe[index].id] else { return amount >= probe[index].targetAmount }
        return date <= target
    }
    guard !onTime(0) else { return 0 }      // успевает и без денег
    guard onTime(cap) else { return cap }   // не успевает даже со всеми
    var low = 0.0, high = cap
    while high - low > 1_000 {
        let mid = ((low + high) / 2 / 1_000).rounded() * 1_000
        if mid <= low || mid >= high { break }
        if onTime(mid) { high = mid } else { low = mid }
    }
    return high
}
```

**Один источник дат.** `forecast` передается снаружи, и это та же функция, которая считает даты на карточках
целей. Поэтому дата после раскладки совпадает с датой, которую человек увидит на соседнем экране. Чтобы никто не
посчитал даты в обход, есть тест-сторож: он падает, если где-то появляется второй расчет прогноза.
[ПЕРЕСКАЖИ: зачем понадобился кеш прогнозов, если бинарный поиск вызывает прогноз много раз.]

### Что получилось

- работает без сети, в том числе на мобильном интернете без VPN;
- отвечает мгновенно;
- один и тот же вход дает один и тот же ответ;
- покрыт тестами: цель без даты, посильная дата, непосильная, очередь, премия.

[ПЕРЕСКАЖИ: как это восприняли пользователи или ты сам, без цифр удержания.]

### Где модель осталась

Там, где нужен текст, а не число: инсайт дня, итоги недели, совет, что сделать дальше. Правила такие:

| Задача | Кто делает |
|---|---|
| Сумма на день, даты целей, раскладка денег | код |
| Хватит ли до получки, на сколько дней | код |
| Объяснить цифру простыми словами | модель |
| Совет на завтра, тон, разрешение порадовать себя | модель |
| Нет сети | запасной текст-шаблон |

### Пять правил, к которым я пришел

1. Цифры считает код. Модель получает их уже посчитанными и не придумывает новые.
2. Один источник для каждой цифры. Если модель называет дату, это дата из движка, а не ее собственная.
3. У каждого текста модели есть запасной шаблон на случай, если сети нет.
4. Если результат можно проверить тестом, это задача для кода.
5. Если ошибка в цифре стоит человеку спокойствия, модель туда не пускаем.

## Статья 2 · ср 07.10 · ФИНАЛ

**Заголовок:** Откуда приходят установки iOS-приложения без SDK: спецстраницы App Store вместо UTM
**Хабы:** Разработка под iOS, Аналитика мобильных приложений, Интернет-маркетинг
**Теги:** App Store, App Store Connect, атрибуция, custom product pages, инди-разработка
**Обложка:** `Кубыш доки и артефакты/Хабр 07.10/2_cover.png` · **в конце статьи:** `Кубыш доки и артефакты/Хабр 07.10/2_checklist.png`
**Ссылка:** спецстраница «01 Хабр» (ppid), одна, в конце.

Я делаю Кубыш, приложение для учета расходов и накоплений на iPhone: оно считает, сколько можно тратить в день до
зарплаты и когда накопишь на цель. Пишу о нем на Хабре, vc.ru, в LinkedIn и соцсетях. После каждой публикации
хотелось понять одно: что из этого приводит людей в App Store.

На сайте эту задачу решает UTM-метка. В App Store так не получится: параметры ссылки до приложения не доходят. SDK
атрибуции для маленького приложения избыточен: еще одна зависимость и передача данных третьей стороне. Поэтому я
посчитал источники стандартными средствами Apple. Ниже как это настроить и на чем я обжегся.

### Что дает Apple без SDK

**Ссылки кампаний.** К ссылке на приложение добавляются `pt` (токен провайдера из App Store Connect) и `ct` (название
кампании). В аналитике App Store Connect появляется разбивка загрузок по кампаниям.

**Специальные страницы продукта** (Custom Product Pages). Это отдельная версия страницы приложения со своими
скриншотами, промо-текстом и ссылкой с параметром `ppid`. В отчете видны просмотры и загрузки по каждой странице.

Я выбрал спецстраницы. Кроме источника, видно, как страница превращает просмотр в загрузку, и под каждую аудиторию
можно поставить свои скриншоты.

### Как настроить за вечер

1. App Store Connect → приложение → «Специальные страницы продукта» → новая страница.
2. Скриншоты и промо-текст под аудиторию канала. Можно оставить как в основной странице, чтобы мерить только источник.
3. Отправить на проверку. Apple проверяет страницу отдельно от версии приложения.
4. Скопировать ссылку с `ppid`. Если нужна короткая ссылка, проверить, что сокращатель не теряет параметр.
5. Одна страница на один канал, номер в названии: «01 Хабр», «02 vc.ru», «06 LinkedIn».

Страницы можно создавать через App Store Connect API, без браузера. Так я завел сразу четыре: для LinkedIn, Тредс,
Макса и Инстаграма.

### Что показали цифры

Самый показательный канал у меня vc.ru: 138 просмотров спецстраницы и 23 загрузки, около 17%. Это люди, которые
дочитали статью и пошли в стор осознанно. Но 23 загрузки это направление, а не статистика.

### На чем я обжегся

1. **Страница не одобрена, а ссылка работает.** До одобрения Apple ссылка с `ppid` открывает обычную страницу, и
   загрузки в отчет страницы не попадают. Проверяйте статус до публикации поста.
2. **Ссылка без спецстраницы.** В одной статье я дал обычную ссылку на App Store, и загрузки с нее не отличить от
   остальных. Ссылку потом можно отредактировать, но первые, самые активные дни уже потеряны.
3. **Отчеты не через API.** Ключ, которым я создавал страницы и обновлял описание, не получает доступ к аналитике.
   Отчеты смотрю в кабинете.
4. **Малые числа.** На десятках загрузок не стоит сравнивать конверсию каналов до процента.

### Ограничения метода

- видно просмотры и загрузки страницы, но не то, что человек делал в приложении дальше;
- данные приходят с задержкой;
- только iOS.

### Шаблон, который можно забрать

- спецстраница на каждый канал, номер в названии;
- проверить ссылку после одобрения, до публикации;
- записать дневную базу загрузок до поста и сравнить через 48 часов;
- выводы делать на сотнях просмотров.

## Пост 3 · формат «Пост» · ФИНАЛ

**Заголовок:** Когда кончаются часовые лимиты, я иду на обед. Когда недельные, у меня выходной
**Теги:** ИИ-агенты, Claude, соло-разработка, продуктивность
**Картинка:** `Кубыш доки и артефакты/Хабр 07.10/3_cover.png`

Я один делаю Кубыш, приложение для личных финансов на iPhone, а код пишет ИИ-агент. У агента два лимита: на
несколько часов и на неделю. За несколько месяцев выяснилось, что они неплохо заменяют тимлида и отдел кадров.

**Часовой лимит = обед.** Агент вежливо говорит «возвращайтесь через пару часов». Можно поесть, погулять и наконец
подумать, что мы вообще строим.

**Недельный лимит = выходной, который ты не планировал.** Работа стоит. В четверг. Релиз подождет.

**Два агента = два сотрудника.** Один ушел на обед посреди задачи, второй открыл его постановку и доделал. Так было в
сентябре: Codex уперся в лимит на середине задачи, Claude прочитал файл с постановкой и журналом и закончил работу.

**Отмена подписки = сокращение штата.** С конца сентября у меня один агент. Штат сократил, план остался прежним.

Что из этого вынес всерьез:

1. Задача живет в файле, а не в чате: зачем, шаги, критерии готовности, журнал. Тогда ее продолжит другой агент или
   ты сам через неделю.
2. Коммит и пуш после каждого шага: обрыв посреди задачи ничего не стоит.
3. Тяжелое, вроде рефакторинга и больших проверок, ставлю на начало недели, пока лимит полный.
4. К концу недели оставляю то, что можно делать без агента: тексты, скриншоты, разговоры с пользователями.

Само приложение, которое так делается, считает деньги от зарплаты до зарплаты: [ссылка «01 Хабр»].

А у вас кто тимлид: лимиты или календарь?
